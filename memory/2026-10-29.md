## 归档：A档默认关 calls、去掉 livekit 收尾

### 改了什么
- A 档源码已在工作区：`zed` / `title_bar` / `settings_ui` / `sidebar` 将通话与音视频改为可选 `calls`/`audio` feature，默认关闭，避免硬链 livekit/libwebrtc/cpal。
- 收尾时发现并修复：`title_bar` 在无 `calls` 时仍调用 `render_call_controls`（定义在 `collab` 模块），导致 `cargo check -p title_bar` 失败；已用 `#[cfg(feature = "calls")]` 分流 trailing 控件与构造期 `observe_diagnostics`。
- 顺手清理无 `calls` 时未使用的 `TaskExt` / `PopoverMenuHandle` import。

### 为什么
- 默认构建降内存；协作通话需显式 `--features calls`。
- 门控不完整会让「默认关 calls」本身编不过。

### 依赖结论
- `cargo tree --edges normal -p zed`（默认）：**无** livekit / webrtc / libwebrtc。
- `cargo tree --edges normal -p zed --features calls`：出现 `livekit_client`、`libwebrtc`、`webrtc-sys` 等（符合预期）。
- feature 统一：`zed::calls` 透传 `settings_ui/audio`、`sidebar/audio`、`title_bar/calls`；各子 crate `default = []`。

### check 结果
- `cargo check -p settings_ui -p sidebar -p title_bar`：**通过**（无 warning）。
- `cargo check -p zed`：**未通过（环境）**——`gpui_apple` Metal 着色器：`xcode-select` 指向 CLT 无 `metal`；切到 `/Applications/Xcode.app` 后报 **Xcode license 未同意**（`sudo xcodebuild -license`）。与 A 档改动无关。

### 关键决策
- 按铁律：**仅 main 本地 commit，不 push、不开分支、不开 PR**。
- memory / 工作汇总单独落盘，不打进本次 A 档 commit。

### 待验证点
- 本机同意 Xcode license 后重跑 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer cargo check -p zed`。
- 需要通话时：`cargo build -p zed --features calls`。
